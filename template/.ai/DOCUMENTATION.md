# Documentation

Use this for new feature thinking and doc updates.

## New features

Before building a feature:

1. Identify the user goal.
2. List the smallest useful version.
3. Check edge cases, authorization, and failure states.
4. Update [`../project.md`](../project.md) when behavior changes.

Keep implementation practices in [`PRACTICES.md`](./PRACTICES.md), especially
the `input.ts` Zod flow for actions, queries, and Route Handlers.
